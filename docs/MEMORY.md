# Memory 容量与并发边界

T09b（2026-11-24）只改变读取/模型上下文与临时缓存，数据库保留全部历史消息，不清理用户历史、不修改会话 TTL 策略。配置默认值及合法范围见 [DEVELOPMENT.md](DEVELOPMENT.md#memory-limits)，测试入口见 [TESTING.md](TESTING.md)。

## 历史读取与模型输入

PostgreSQL get_session按ordinal倒序LIMIT后恢复正序，默认最多100条消息；单独查询总message_count，公开SessionDetail的总计数语义不变。快照的_persisted_message_count记录当前窗口中已持久化的条数，save_session只追加其后新消息，仍使用父行锁/批次幂等，不把历史窗口回写成完整历史。返回窗口保留原消息元数据；所有旧记录仍在数据库，导出/恢复工具继续读取原表。

Memory默认最近10条最多8000 UTF-8字节，较早历史摘要输入最多16000字节，摘要输出最多4000字节，文件名上下文最多4000字节。仅从最后100条历史和最后100个文件名构造上下文；超长内容先按字符切片再编码，避免临时编码完整巨型字符串。截取时保留最近消息的尾部，并保留角色与UTF-8字符边界。已明确generation_status为failed/cancelled的assistant内容不用于摘要或近期上下文。较长/截断历史附加窗口提示，不能把窗口摘要当作完整对话归档。

这些是字节/条数边界，不是供应商精确Tokenizer计数。T03仍在网关按保守Token与费用预算准入，并以实际供应商usage结算。RAG文档内容、检索顺序、文件名/页码引用不由Memory改写；有限窗口可能省略较早对话信息，未通过真实模型证明任意长对话语义连续性。

历史行的完整JSONB元数据仍读取，窗口限制不等于数据库存储配额或单条历史记录的SQL字节上限；历史巨大单条记录及总count查询的成本需按实际规模进一步评估。前端本地历史仍沿用现有保存机制，不因本项自动删除。

## 缓存及在途计算

缓存为进程内有界LRU，默认128项、900秒单调时钟TTL。key包括明确session范围、实际受限历史内容的SHA-256、受限文件上下文和摘要输出限额。相同文本的不同session不共享；无session时仅在同一UsageTracker的随机request范围复用，无session且无tracker则不使用共享缓存。版本不同不会互相覆盖。

全局锁仅保护有界缓存/在途索引，模型I/O在锁外。相同key的并发摘要用Event合并，只有发起者经过原T03网关产生一次实际调用与usage；等待者不复制用量，也不附加修复调用。等待受自身T03截止/取消限制，无tracker时最多等5秒；超时或在途容量已满降级，不另发模型请求。在途索引同样受缓存条数上限约束。发起者失败/取消时finally清理索引并唤醒等待者。

空/非法摘要、模型失败不写成功缓存；以受控原因返回可识别的摘要不可用结果，不发修复调用。Memory模型失败但正文成功时，T06整体/专业节点标记degraded，并保留失败调用的实际或未知usage，未知费用不变成免费。下一次独立用户请求仍可尝试，系统不自动重发生成。

显式删除、过期读取删除和TTL清理在事务完成后失效本进程相应缓存；在途摘要被标记失效，不能发布回成功缓存。其他工作进程有各自缓存，后续请求仍先验证数据库会话；缓存不是授权来源。主动删除与在途生成的边界仍以[T06/T05a执行契约](EXECUTION.md)为准，T04所有权机制未由本项实现。

结构化事件只记录命中、容量、失效及受控回退原因，不记录历史/摘要/PDF正文或缓存key。现有日志session_id策略仍属于T02b，不能据此宣称全链路脱敏。
