审计日期：2026-11-24（Asia/Shanghai）。代码基线：`370bb47`，本地 `main`；开始时工作区干净。只修改 `plans/` 文档，不修改业务代码，不推送、不部署、不访问生产数据库或调用付费 API。

## 1. 结论与依据

项目已经形成可工作的模块化单体：FastAPI 服务、React 界面、LangGraph 编排、统一 LLM 客户端、PostgreSQL 关系数据与 pgvector 检索。**本地存储迁移已经实现，不应再安排第二次迁移。下一阶段应补访问、资源和失败边界，而非增加 Agent 或基础设施。**

当前适合作为受控的本地应用和演示工程基础；仓库不足以证明它已经具备公开服务的权限保护、费用上限、持续灾难恢复和生产容量保证。没有确认 P0 泄露或数据损坏事件；不把可见风险当作已发生事故，也不据单元测试通过作安全认证。

审计范围：`app/`、`agent/`、`tools/`、`utils/`、`evaluation/`、前端源码与测试、`migration_tools/`、Alembic、全部测试模块、README 双语、`docs/`、既有规划、Docker/Compose/CI/devcontainer、环境示例与忽略规则；并核对 Git 历史。依赖 lockfile 用于核对锁定机制，不对每个第三方包源码作安全审计；未扫描远端依赖漏洞或读取私有 PDF/数据库内容。PDF 只用于显式的本地证据引文校验。未检查线上实际配置、账单、GitHub Actions 运行结果。

近期提交与实现相符：`39ea80c` 实现部分异常脱敏；`cf75fa3` 实现 PG/pgvector 与回归；`9adff7e` / `370bb47` 重写双语 README。本轮没有新业务实现。

### 保留的设计

- `app/services/` 分隔 HTTP 与工作流；Graph 不直接执行 HTTP/SQL。保持现有函数和字典契约，不新增通用 repository 框架。
- `app/db/engine.py:10–31` 的有限连接池、UTC、pre_ping、隐藏参数；连接不跨 Embedding/LLM/SSE 等待。
- `app/services/postgres_store.py:72–120` 的父会话行锁、消息批次追加、文档/Chunk/页数原子提交；FK 与唯一约束见 `app/db/schema.py:18–58`。不再有活跃路径跨 SQLite/FAISS 两套持久化的问题。
- `utils/pgvector_store.py:26–39` 先限制 session/profile，再精确 cosine top-k；复合 FK 阻止 Chunk 关联其他会话文档。保留 1024 维单位 BGE-M3 profile，不立即加 HNSW。
- Planner 规则快路径、Source 零 LLM、单 Specialist 免 Reviewer 调用、最多一次补充步骤，以及 `copy_context` 传播线程用量。不要为“规范化”抹掉这些成本优化。
- StaticVectorStore 与真实 PDF 评估分离；Judge 单独接收标注；用量区分 Agent/Judge、缓存未知/零命中/无调用、USD/CNY 独立估算。
- Docker 非 root、多阶段前端构建、固定 PDF 解析版本、FAISS 独立迁移依赖；迁移工具不覆盖原文件、禁用破坏性 downgrade。

## 5. 架构与数据一致性进一步说明

数据库内同会话写入已通过父行锁串行化；消息批次可以对同一内存批次重试判重，不能当成 HTTP 请求幂等。每次新请求会生成新 batch；浏览器重发可能再次调用模型。JSONB 存完整 payload 保留扩展字段，这一设计应保留。

会话删除与 Chunk 级联已实现；不需要再建设 FAISS 文件代次。尚未解决的是在途租约、全部历史读取、锁等待和迁移边界验证。`verify_schema` 只确认 revision/扩展存在，不能替代 schema drift、角色权限和依赖容量验证。SQL 通过 Core 参数化，未发现将用户输入拼接成生产 SQL 的路径；这不是完整渗透测试结论。

资料安全不仅是错误脱敏：PDF 正文与用户问题会发送到 DeepSeek，pgvector/浏览器保留文本；需在 T02b 明确保留和外发说明。ReactMarkdown 没有启用原始 HTML 插件，未发现直接 dangerouslySetInnerHTML；仍须审查外部链接/图片和响应类型边界，不据此宣称完全抗 XSS 或抗提示注入。
